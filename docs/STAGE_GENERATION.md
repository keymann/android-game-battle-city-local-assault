# 스테이지 랜덤 생성

`assets/RANDOM_MAP_ASSET_GUIDE.md` 를 구현한 것이다. 규칙 값은 전부
`app/src/main/assets/manifest/mapgen.json` 에서 온다. 코드에는 숫자가 없다.

| 파일 | 맡은 일 |
|---|---|
| `manifest/mapgen.json` | 크기 · 밀도 · 군집 · 검증 기준 · variation 가중치 |
| `map/MapGenProfile.kt` | 위 파일 리더 |
| `map/StageGenerator.kt` | 생성 · 검증 · 수선 |
| `map/StageData.kt` | 완성된 스테이지와 검증 결과 |

---

## 1. 경로를 장애물보다 먼저 만든다

가이드가 가장 힘주어 말하는 원칙이다. 장애물을 무작위로 뿌린 뒤 빈 곳을 찾는 방식은
막힌 스폰과 불공정한 본진 경로를 쉽게 만든다.

```
1 예약   본진 / 플레이어 스폰 / 적 스폰과 그 주변 3x3
2 경로   본진 -> 중앙 -> 각 적 스폰. 폭 2. 순환로까지
3 지형   물 -> 강철 -> 벽돌 -> 숲 -> 얼음 순으로 군집 배치
4 소품   모래주머니 / 상자 / 드럼통 / 바위
5 검증   연결성 / 본진 출구 / 공정성 -> 점수
6 수선   실패하면 고치고 다시 검증. 8번 넘으면 seed 를 버린다
7 그림   좌표 해시로 variation 선택
```

예약된 칸에는 지형이 들어가지 않는다. 그래서 경로가 나중에 막히는 일이 없다.

## 2. 좌표계 — 가이드의 "타일" 은 이 게임의 블록이다

가이드는 한 칸을 "타일" 이라 부른다. 이 게임에서 그것은 **block(64px)** 이다.
지형 한 장이 탱크 한 대 크기라는 원작 규칙과 같다.

파괴는 그보다 잘게 **cell(32px)** 단위로 일어난다. 그래서 완성 단계에서 블록 하나를
셀 2×2 로 펼쳐 저장한다. 벽돌 한 블록을 반만 부수면 나머지 반이 남는다.

소품(드럼통·상자)만 예외로 셀 하나를 차지한다. 블록만 하게 그리면 탱크만큼 커진다.

### 맵 크기는 16:9 로 옮겼다

가이드 권장은 20×16 / 24×18 / 28×20 인데 가로세로비가 1.25~1.40 이다. 맵 전체를 한
화면에 보여 주는 이 게임에서는 위아래에 큰 여백이 생긴다. 칸 수는 가이드의 증가
폭(1 : 1.35 : 1.75)을 지키되 16:9 에 가장 가까운 정수 격자로 바꿨다.

| 인원 | 격자 | 칸 수 | 16:9 대비 |
|---:|---|---:|---:|
| 2 | 23 × 13 | 299 | −0.48% |
| 3 | 28 × 16 | 448 | −1.56% |
| 4 | 32 × 18 | 576 | 정확 |

## 3. 연결성은 블록이 아니라 탱크 발자국으로 잰다

블록 단위로 재면 **실제로는 못 지나가는 한 칸짜리 틈**을 통과할 수 있다고 착각한다.
탱크는 2×2 셀을 차지하므로, 검증도 셀 격자에서 2×2 발자국이 들어가는 자리만 이어
붙여 잰다. AI 가 쓰는 `NavGrid` 와 같은 잣대다.

검증 항목은 가이드 §9·§10 그대로다.

- 가장 큰 연결 덩어리가 전체의 90% 이상
- 본진에서 나가는 서로 다른 방향이 3개 이상
- 모든 스폰이 중앙과 이어짐
- 플레이어별 중앙까지 거리 편차 ±15%
- 가장 가까운 적 스폰까지 거리 편차 ±18%
- 10스텝 안 이동 면적 최대/최소 1.25 이하

---

## 4. 공정성을 맞추는 두 가지

**좌우로 접는다.** 완전 대칭 맵이 필요한 것은 아니지만, 지형을 비대칭으로 두면
한쪽 플레이어만 물이나 강철에 갇혀 거리 편차 18% 를 넘기기 쉽다. 접는 축은
**본진이 선 열**이다. 맵 한가운데로 잡으면 칸 수가 짝수일 때 본진·스폰과 반 칸
어긋나 대칭이 깨진다.

**불리한 쪽을 덜어 낸다.** 좌우로 접어도 안쪽 두 명과 바깥 두 명의 형편은 다르다.
안쪽은 본진 방벽에 붙어 있고 바깥은 개활지에 선다. 그 차이가 1.25배를 넘으면
가이드 §16-6 대로 가장 불리한 플레이어 둘레의 벽을 걷어 낸다. 벽돌부터 걷고,
그것으로 모자랄 때만 물과 강철에 손댄다. 물과 강철은 밀도 하한이 있기 때문이다.

---

## 5. 밀도는 마지막에 한 번 맞춘다

군집을 키우다 보면 자리가 없어 목표를 못 채우고, 좌우로 접으면 반대로 넘친다.
둘 다 프로필 위반이라 마지막에 모자란 것은 채우고 넘친 것은 덜어 낸다.

- 채울 때는 **이미 있는 덩어리 옆**에만 붙인다. 아무 데나 뿌리면 소금·후추가 된다.
- 덜어 낼 때는 **가장자리부터** 지운다. 가운데를 파면 군집이 도넛처럼 뚫린다.
- 하한 칸 수는 올림한다. 내림하면 23.04 칸이 23 칸이 되어 하한을 아슬아슬하게 못 넘는다.

## 6. 점수 (가이드 §15)

| 항목 | 점수 |
|---|---:|
| 연결성 | 30 |
| 공정성 | 20 |
| 본진 균형 | 15 |
| 스폰 안전 | 15 |
| 군집 | 10 |
| 다양성 | 10 |

85점 이상이면 쓰고, 필수 규칙을 하나라도 어기면 점수와 무관하게 버린다.

공정성 점수는 **허용치를 1.0 으로 놓고** 잰다. 딱 한계선이면 절반, 여유가 있을수록
높다. 처음에는 한계선을 0점으로 뒀는데, 가이드의 필수 규칙을 모두 지킨 맵이 85점을
못 넘어 전부 폐기됐다. 규칙을 지킨 맵은 쓸 수 있어야 한다.

## 7. 그림 고르기 (가이드 §12)

```
variationIndex = hash(seed, x, y, 의미타입) mod 후보수
```

난수기를 돌리지 않고 좌표를 해싱한다. 그래야 Host 와 Client 가 서로 다른 순서로
값을 뽑아도 같은 그림이 나온다.

바닥 기조는 이웃을 보고 정한다. 완전 독립 난수로 뿌리면 소금·후추가 된다.

| 이웃 | 바닥 |
|---|---|
| 물가 | 무성한 풀 |
| 숲 | 마른 풀 |
| 벽이 많음 | 갈라진 흙 |
| 적 스폰 근처 | 그을린 흙 |

파괴·경고 상태 그림(`brick_damage_*`, `base_destroyed`, `crate_broken` …)은 초기
배치에 쓰지 않는다. (가이드 §13) 매니페스트가 실수로 넣더라도 생성기가 걸러 낸다.

---

## 8. 검증은 테스트가 대신 본다

가이드 §19 최종 체크리스트를 `MapGuideTest` 로 옮겼다. 여러 seed 를 돌려
본진 개수 · 스폰 수와 간격 · 3×3 안전 · 본진 출구 · 연결 비율 · 밀도 범위 ·
군집 비율 · 결정론을 기계가 확인한다.
