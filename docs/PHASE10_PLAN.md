# Phase 10 — 네트워크 동기화 결함 수정 계획

[2026-08-20 감사 결과](NETWORK_SYNC_AUDIT_2026-08-20.md)에서 찾은 출시 차단 항목을 고친다.
범위는 **P0 한 건과 P1 여섯 건**이다. P2 세 건과 식별자 체계(sessionId·matchId·playerId)는
다음 단계로 미룬다.

## 확정한 정책

감사 결과를 놓고 다음을 정했다.

| 갈림길 | 정한 것 |
|---|---|
| Host 가 끊겼을 때 Client 가 갈 곳 | 결과 화면에 `HOST DISCONNECTED` 를 띄우고, 승자와 점수는 확정하지 않는다. 사용자가 MAIN MENU 로 나간다 |
| 끊긴 참가자의 탱크 | 즉시 탈락으로 확정하고 탱크를 걷어낸다 |
| 부서진 타일 전달 | 스냅샷에 변경 셀을 실어 보낸다. 유실은 다음 스냅샷이 덮는다 |

## 어떻게 고칠 것인가

### 1. 타일과 본진 상태 전파 (`10-MAP-04`, `10-BASE-06`)

`TileMap` 이 바뀐 셀을 적어 둔다. Host 는 스냅샷마다 최근 창(window) 안의 변경 셀을
실어 보내고, Client 는 그대로 자기 맵에 놓는다.

- 창 크기는 스냅샷 세 장이다. 같은 변경을 세 번 보내므로 연속 두 번 유실까지 견딘다.
- 한 패킷에 실을 수 있는 셀 수를 제한한다. 넘치면 오래된 것부터 보내고 나머지는
  다음 스냅샷으로 넘긴다.
- 본진은 파괴 여부와 보호막 여부를 한 바이트에 담는다.

ACK 를 쓰지 않는 이유는 스냅샷이 최신 값 채널이기 때문이다. 늦게 도착한 변경이 최신
상태를 되돌리지 않도록, 값은 셀의 **현재 종류**를 보낸다. 순서가 뒤바뀌어도 다음
스냅샷이 바로잡는다.

### 2. 맵 해시 검증 (`05-COMMIT-02`)

지금은 Host 가 **이전 판** 스테이지 해시를 싣고 Client 는 **새 판** 해시와 견준다.
언제나 어긋나고 로그만 남는다.

Host 가 START 를 보내기 전에 이번 판 스테이지를 미리 만들어 두고 그 해시를 싣는다.
만들어 둔 스테이지는 판을 열 때 그대로 쓰므로 두 번 만들지 않는다.

Client 는 해시가 어긋나면 판을 열지 않는다. 방을 나가고 사유를 띄운다.

### 3. 끊긴 참가자 (`13-CLIENT-08`)

Host 가 연결 끊김을 확정하면 그 자리를 탈락으로 굳히고 탱크를 걷어낸다. 남은 Life 는
보지 않는다. 점수는 끊긴 순간 값으로 남는다.

### 4. 유령 이동 (`07-INPUT-07`)

Host 가 자리마다 마지막 입력 시각을 적어 둔다. 일정 시간 새 입력이 없으면 이동을
멈춘다. 방향은 그대로 둔다. 참가자는 매 틱 입력을 보내므로 정상 상황에서는 걸리지 않는다.

### 5. 설정 변경과 Ready (`04-SETTINGS-05`)

방장이 규칙을 바꾸면 참가자 Ready 를 모두 해제한다. 방장 자신은 준비한 채로 둔다.
바뀐 값이 없으면 해제하지 않는다.

### 6. Host 끊김 (`13-HOST-03`)

Client 가 Host 를 잃으면 전투를 멈추고 결과 화면으로 간다. 화면에는 `HOST DISCONNECTED`
가 뜨고 PLAY AGAIN 과 LOBBY 는 잠긴다. MAIN MENU 만 열려 있다. 로비에서 잃었을 때는
곧바로 메인 메뉴로 돌아간다.

## 프로토콜

스냅샷 형식이 바뀌므로 `Protocol.VERSION` 을 2 로 올린다. 버전이 다른 기기끼리는
패킷을 서로 버린다.

## 검증

- 단위·통합 테스트를 늘린다. 타일 전파, 해시 불일치 중단, 탈락 처리, 입력 타임아웃,
  Ready 해제, Host 끊김 경로를 `LoopbackTransport` 위에서 확인한다.
- 실기기 두 대 시험은 여전히 못 한다. 감사 결과 부록 B 절차를 그대로 남겨 둔다.
