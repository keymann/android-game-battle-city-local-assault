# 리소스 적용 결과 (Asset Selection)

게임에 쓰는 그림은 전부 `assets/` 의 **자체 제작 에셋 팩**에서 온다.
글자만 예외로 Kenney *Desert Shooter Pack*(CC0)의 비트맵 폰트를 쓴다. 팩에 글자가 없다.

---

## 1. 무엇을 어디서 가져오나

| 게임 요소 | 출처 | 장수 |
|---|---|---:|
| 바닥 / 벽돌 / 강철 / 물 / 숲 / 얼음 / 본진 / 소품 | `assets/sprites/terrain` | 48 |
| 탱크 (플레이어 3종 · COM 3종 × 4방향) | `assets/sprites/tanks` | 24 |
| 포탄 · 총구 화염 · 피격 · 폭발 · 방어막 · 대시 · 스폰 | `assets/sprites/effects` | 32 |
| HUD 아이콘 | `assets/hud/components` | 16 |
| 비트맵 폰트 (A~Z, 0~9) | `assets/font` | 75 |
| 런처 아이콘 | `assets/app_icon` | 5 |
| 시작 화면 | `assets/splash` | 1 |

`tools/build_atlas.py` 가 이것들을 **한 장**으로 묶어
`app/src/main/assets/atlas/game.png` + `game.xml` 을 만든다.

---

## 2. 아틀라스가 한 장인 이유

지형·탱크·이펙트·HUD 가 모두 같은 팩에서 나오고 화풍이 같다. 나눌 이유가 없다.

전에는 두 장이었다. 픽셀아트 타일은 NEAREST, 회전하는 탱크는 LINEAR 로 뽑아야 해서
필터가 달랐기 때문이다. 이번 팩은 **탱크가 4방향으로 미리 그려져 있어 회전이 없다.**
회전이 없으니 전부 NEAREST 로 뽑을 수 있고, 그러면 텍스처를 나눌 이유가 사라진다.

한 프레임 안에서 텍스처 교체가 한 번도 일어나지 않는다. 배치 실행 횟수가 6에서 2로 줄었다.

```
아틀라스  1024 x 748,  스프라이트 195장
```

---

## 3. 격자 수치를 믿지 않는다

팩에는 세 갈래 파일이 들어 있다.

```
components_sheet_rgba.png   원본 해상도, 배경이 빠진 판   <- 이걸 쓴다
components_atlas_128.png    128 격자로 다시 앉힌 판
components_atlas.json       이름과 순서
```

128 격자판을 그대로 쓰려다 뒤쪽 칸이 잘려 나오는 것을 발견했다. 스프라이트 간격이
실제로는 120px 남짓이라 칸이 갈수록 밀린다. 여덟 번째 칸은 절반이 옆 칸에 가 있었다.

그래서 **그림은 원본 판에서 직접 찾고, 이름과 순서만 JSON 에서 가져온다.**
찾는 방법은 눈금이 아니라 빈 줄이다. 알파가 비어 있는 가로줄로 띠를 가르고, 띠 안에서
빈 세로줄로 칸을 가른다. 세 시트 모두 JSON 의 장수와 정확히 맞아떨어진다.

---

## 4. 이어 붙는 타일과 한 칸짜리 물건

팩의 타일은 **스티커** 모양이다. 모서리가 둥글고 바깥에 윤곽선이 둘려 있다.

| 갈래 | 다루는 법 |
|---|---|
| 바닥 · 물 · 얼음 | 테두리를 깎고 정확히 64×64 로 늘린다 |
| 벽돌 · 강철 · 숲 | 그대로 둔다. 윤곽선이 곧 블록의 생김새다 |
| 소품 · 본진 | 비율을 지켜 줄인다 |

깎을 두께는 눈으로 어림잡지 않는다. 테두리 한 줄이 **전부 불투명**하고 그 줄의 밝기가
**속과 비슷**해지는 첫 지점을 찾아 그만큼 깎는다. (`tools/atlaslib.py` 의 `tile_inset`)

두 가지를 배웠다.

- 밝기는 위아래 양쪽으로 봐야 한다. 물 타일은 바깥에 **밝은** 물결 테두리가 둘려 있어서
  "어두우면 깎는다" 로는 한 줄도 못 깎았다.
- 한 줄만 보고 끝내면 안 된다. 물 테두리는 점선이라 어쩌다 한 줄이 속과 비슷해 보인다.
  세 줄이 내리 통과해야 인정한다.

같은 갈래는 **가장 두꺼운 값으로 통일**한다. 타일마다 실측값을 따로 쓰면 물 네 장이
서로 다른 배율로 줄어들어 물결 굵기가 칸마다 달라 보인다.

---

## 5. 탱크는 차체를 기준으로 맞춘다

방향마다 그림이 따로 있다. 그런데 포신이 뻗은 쪽으로 그림이 길어져서, 그림 전체의
한가운데를 맞추면 방향을 꺾을 때마다 탱크가 튄다.

포신을 빼고 **궤도가 있는 구간**만 보고 한가운데를 잡는다. 축을 가려서 봐야 한다.

```
포신과 직각인 축  궤도가 끝에서 끝까지 차 있다. 전체 테두리가 곧 차체다.
포신과 나란한 축  포신 때문에 길어져 있다. 궤도가 있는 구간만 골라낸다.
```

처음에는 축을 가리지 않고 "두꺼운 줄" 만 찾았는데, 좌우를 보는 탱크에서는 포신이
가로지르는 줄이 가장 넓어서 그 한 줄만 차체로 잡혔다. 배율이 터무니없이 커져
탱크 한 대가 화면 한 칸을 가득 채웠다.

차체 너비를 정확히 **한 블록(64px)** 에 맞추고, 캔버스는 96px 로 두어 포신이 밖으로
뻗을 자리를 남긴다.

---

## 6. 아직 안 쓰는 것

팩에 들어 있지만 이번 단계에서 화면에 나오지 않는 것들이다. 다음 단계에서 쓴다.

| 리소스 | 쓸 곳 |
|---|---|
| `assets/lobby/` 전체 | Phase 6 로비 |
| 조이스틱 · FIRE · SPECIAL 버튼 | Phase 7 모바일 조작 |
| 네트워크 신호 아이콘 | Phase 6 접속 상태 |
| `assets/audio/` 전체 (BGM 4곡, 효과음 19종) | Phase 8 사운드 |

조작 UI 와 네트워크 아이콘은 이미 매니페스트 `hud.controls` / `hud.network` 에
이름을 잡아 두었다. 아틀라스에도 들어 있어 그리기만 하면 된다.

---

## 7. 다시 만들기

```bash
tools/build_atlas.py
```

`assets/` 를 읽어 `app/src/main/assets/atlas/game.png` 와 `game.xml` 을 다시 쓴다.
중간 결과는 `build/atlas/sprites/` 에 남으므로 한 장씩 눈으로 확인할 수 있다.
