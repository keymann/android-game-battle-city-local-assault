# 화면과 방 설정

계획서 §27 · §28 · §33 · §44.2 를 옮긴 것이다. 판을 굴리는 코드가 아니라 **판 앞뒤로
사람이 지나가는 길**에 관한 문서다.

| 파일 | 맡은 일 |
|---|---|
| `game/GameHost.kt` | 화면 사이의 갈림길과 손가락 배분 |
| `game/MainMenuScene.kt` | 방 만들기 · 방 들어가기 · 사운드 설정 |
| `game/RoomListScene.kt` | 같은 망에 열린 방 목록 |
| `game/GameSettingsScene.kt` | 방 규칙 (로비에서 방장만) |
| `game/SoundSettingsScene.kt` | 이 기기의 소리 크기 (메인 메뉴) |
| `game/SettingsLayout.kt` | 설정판 두 장이 함께 쓰는 자리 계산 |
| `game/LoopQueue.kt` | 손가락이 만든 일감을 루프 스레드로 넘긴다 |
| `game/ResultScene.kt` 의 `solo` | 혼자 하는 판의 결과 화면 (RESTART) |
| `game/ResultScene.kt` | 순위 · 승자 · 다음 판 |
| `game/RoomSettings.kt` | 방 규칙 · 기기 설정 값 |
| `game/SettingsStore.kt` | 기기 설정을 남긴다 |
| `render/ScreenUi.kt` | 화면 UI 를 그리는 공용 도구 |
| `net/RoomScanner.kt` | 메뉴에서 같은 망의 방을 세어 본다 |

## 1. 화면 상태 머신

```
         ┌──CREATE─────────────────┐
  MENU ──┤                         ▼
         └──JOIN──▶ ROOMS ──선택──▶ LOBBY ──START──▶ BATTLE ──승패──▶ RESULT
    ▲                  │              ▲   ◀──LOBBY───────────────────┘ │
    │                  │              └───PLAY AGAIN────────────────────┘ │
    └───MAIN MENU──────┴───────────────────────────────────────────────────┘
```

로비와 결과 화면에는 메인 메뉴로 나가는 단추가 있다. 나가면 방이 닫히고(참가자에게는
`HOST_CLOSED` 가 간다) 다시 같은 망을 살피기 시작한다. 로비의 단추는 오른쪽 아래에
둔다 — 다 모여서 시작하려는 순간에 잘못 눌러 방을 나가 버리면 남은 사람들까지
기다리게 되므로 시작 단추와 멀리 떨어뜨린다.

`GameHost.screen` 하나가 지금 무엇을 그리고 손가락을 어디로 보낼지 정한다. 화면
하나가 다른 화면의 사정을 알 필요가 없도록 갈림길은 전부 이 자리에 모았다.

손가락은 **어디를 눌렀는지만** 그 자리에서 가른다. 눌러서 일어나는 일은
`LoopQueue` 에 쌓아 두고 게임 루프 스레드가 다음 틱에 꺼내 실행한다. 세션을 손가락이
온 스레드에서 만지면 패킷이 조용히 사라지기 때문이다
(→ [NETWORK.md](NETWORK.md) §3).

설정 화면은 **두 장으로 갈라 두었다.** 어느 쪽이든 열리면 **혼자 화면을 다 쓴다.**
뒤 화면이 비쳐 보이면 어느 쪽을 누르는 것인지 헷갈리고, 판 밖으로 삐져나온 글자가
설정의 일부처럼 읽힌다.

| 화면 | 어디서 여는가 | 누가 | 담는 것 |
|---|---|---|---|
| 게임 설정 | 로비 오른쪽 위 톱니 | **방장만** | 맵 크기 · 시드 · 아군 오사 · 본진 보호 · 동시 COM 수 |
| 사운드 설정 | 메인 메뉴 오른쪽 아래 스피커 | 누구나 | BGM · SFX 크기 |

한 장에 함께 두었던 것을 가른 까닭은 둘의 임자가 다르기 때문이다(→ §3). 방 규칙은
방장 것이라 참가자에게는 읽기 전용으로 보여 줬는데, 고칠 수 없는 값을 보여 주면 왜
안 되는지부터 설명해야 한다. 소리 크기는 반대로 방과 아무 상관이 없어서 방에
들어가야만 고칠 수 있을 이유가 없었다. 그래서 로비 톱니는 **방장에게만** 그리고,
소리는 메인 메뉴에서 언제나 연다.

갈라 놓으니 판 하나에 담을 것이 줄었다. 예전에는 한 판을 두 칸으로 쪼개 방 규칙과
소리를 반쪽씩 밀어 넣었는데, 이제 줄마다 판 너비를 다 쓴다. 남은 자리는 글자 크기와
줄 간격에 돌렸다 — 이름표 0.5칸 → 0.62칸, 줄 간격 1.4칸 → 게임 설정 1.5칸 ·
사운드 2.0칸. 조작기도 0.95칸에서 1.15칸으로 키워 손가락이 덜 빗나간다.

두 판의 자리 계산은 `SettingsLayout` 한 곳에 모았다. 판 크기 · 줄 간격 · 눈금 치수를
화면마다 `Metrics` 로 넘긴다. 씬은 실제 텍스처를 물고 있어 단위 시험에서 만들 수
없으므로, 계산만 떼어 두면 "줄이 아래 단추 위로 올라가지 않는가", "가장 긴 값이 판
테두리를 물지 않는가" 를 시험이 직접 짚을 수 있다 (`SettingsSplitTest`).

사운드 설정 단추는 설정판의 스피커 그림(`set_speaker_on`)을 쓴다. 톱니는 "설정 전부"
로 읽히는데 거기서 열리는 것은 소리뿐이다. 그 그림은 예전에 쓸 자리가 없어
아틀라스에서 빼 두었던 것을 다시 넣었고, 대신 쓰이지 않게 된 메뉴의 톱니
(`menu_settings_button_normal`)를 뺐다. (`tools/build_atlas.py` 의 `SKIP_ICONS`)

전투 화면으로 넘어가는 신호는 세션이 준다(`NetDriver.onMatchStarted`). 카운트다운이
언제 끝나는지는 세션만 알고, 로비에서 기다리는 사람과 결과 화면에서 기다리는 사람이
같은 신호로 함께 넘어가야 한다.

실행 인자로 메뉴를 건너뛸 수 있다. 두 기기를 붙여 시험할 때 손이 덜 간다.

```
adb shell am start -n com.kophas.battlecity/.MainActivity --es netRole host
adb shell am start -n com.kophas.battlecity/.MainActivity --es netRole client --es hostAddress 192.168.0.5
adb shell am start -n com.kophas.battlecity/.MainActivity --es netRole solo
```

### 시작 화면

앱을 **처음 띄울 때만** 시작 그림을 2초 붙들었다가 메뉴로 넘어간다. 창 배경
(`splash_window`)은 서피스가 준비되는 순간 사라지는데 요즘 기기에서는 그게 눈
깜빡할 사이라 무엇이 지나갔는지 알 수 없다.

프로세스가 살아 있는 동안 다시 들어오는 것은 시작이 아니라 **돌아오는 것**이다.
그때마다 2초를 기다리게 하면 성가시므로, 보여 줬다는 표시를 프로세스에 매단다.
앱이 메모리에서 내려가면 그 표시도 함께 사라져 다음 실행에서 다시 보인다.

### 혼자 하는 판 (화면에 적지 않는다)

밸런스를 눈으로 확인하려면 사람을 둘 모아야 했다. 최소 인원이 두 명이라(계획서 §28)
로비에서 시작할 수 없기 때문이다. 그러느라 확인이 미뤄지고, 미뤄진 만큼 어려운 판을
그대로 두게 됐다. 그래서 **로비에서 내 자리 카드를 10초 누르고 있으면** 혼자 하는
판이 열린다.

| | |
|---|---|
| 어디서 | 로비. 내 자리 카드(내 탱크 그림) |
| 얼마나 | 10초 (`LobbyScene.SOLO_HOLD_SECONDS`) |
| 무엇이 열리나 | 사람 1명 + COM 20기(동시 8기). 로비에서 고른 이름 · 탱크 · 색을 그대로 들고 간다 |
| 방은 | 닫는다. 혼자 하는 판에 방이 남아 있으면 남이 들어와 빈 로비를 본다 |
| 결과 화면 | 큰 단추가 **RESTART** 다. 같은 난이도를 새 맵으로 다시 연다. 로비 단추는 잠근다 |

- **10초인 이유** — 카드를 눌러 준비를 뒤집는 손짓과 섞이지 않아야 한다. 짧게 잡으면
  모르고 눌러 방을 깬다. 카드를 누르면 준비도 함께 뒤집힌다. 그것은 그대로 둔다.
- **2초부터 눈금이 보인다** — 처음부터 보여 주면 카드를 누를 때마다 번쩍여 화면에
  적힌 길처럼 읽힌다. 끝까지 아무것도 없으면 아는 사람도 되는지 몰라 손을 뗀다.
- **세는 중에는 받지 않는다** — 곧 판이 열리는데 다른 판을 열 이유가 없다. 누르고
  있는 동안 세기가 시작되면 붙들기를 버린다.
- 시간은 게임 루프가 더한다. 손가락은 누르기 시작했다는 것만 알린다. 화면이 멈춘
  동안(일시정지) 시간이 흐르지 않고, 두 스레드가 같은 시계를 볼 필요도 없다.
  (→ [NETWORK.md](NETWORK.md) §3)

## 2. 방 목록

JOIN 을 누르면 바로 붙지 않고 목록을 보여 준다. 같은 공유기 아래에 방이 여럿일 수
있고, 어느 방에 들어갈지는 사람이 골라야 한다.

```
              ROOM LIST
   ┌──────────────────────────────┐
   │ NIL    0820 09:33        2-4 │
   │ P2     0820 09:50   FULL 4-4 │   ← 잠김
   └──────────────────────────────┘
        [ REFRESH ]  [ MAIN MENU ]
```

한 줄에 **방장 이름 · 방을 연 시각(MMDD HH:mm) · 인원(방장 포함)** 이 나간다.
시각은 방장 기기의 시계를 이 기기의 시간대로 읽은 것이다. 날짜까지 남긴 이유는
자정을 넘겨 켜 둔 방을 가르기 위해서다.

- **로비에서 기다리는 방만** 나온다. 이미 시작한 방은 들어갈 수 없으므로 목록에
  두면 눌러 보고 나서야 알게 된다.
- **정원이 찬 방은 지우지 않고 잠근다.** 자리가 날 수도 있고, 방이 있다는 것 자체가
  알 만한 정보다.
- **REFRESH** 는 목록을 통째로 버리고 다시 묻는다. 사라진 방을 지우는 데에는 답이
  끊긴 것을 알아채는 시간(3초)이 걸리는데, 사람이 직접 새로 고치겠다고 하면
  기다릴 이유가 없다.
- 방을 고른 뒤 자리를 받을 때까지는 **목록에 머문다.** 들어가지도 못했는데 로비를
  보여 주면 남의 방에 들어간 것처럼 읽힌다.

고른 순간과 들어가는 순간 사이에 방이 바뀔 수 있다. 그 사이를 없앨 수는 없으므로
거절당한 까닭을 목록에 반영한다.

| 거절 | 목록에 하는 일 |
|---|---|
| `ROOM_FULL` | 그 줄을 잠근다 (자리가 나면 다음 알림에 풀린다) |
| `ALREADY_STARTED` | 그 줄을 지운다 |

콜론(`:`)은 Kenney 시트에 없어서 같은 화풍으로 직접 그려 아틀라스에 얹었다.
(`tools/build_atlas.py` 의 `build_colon`)

### 로비 아래 큰 단추

화면에서 가장 크고 가운데 있는 것을 눌렀는데 아무 일도 없으면 고장으로 읽힌다.
그래서 이 단추는 **누가 보느냐에 따라 하는 일이 다르다.**

| 보는 사람 | 쓰인 말 | 누르면 |
|---|---|---|
| 참가자 | `READY` / `CANCEL READY` | 준비 상태를 뒤집는다 |
| 방장 (아직 못 시작) | `WAIT PLAYERS` | 아무 일도 없다 |
| 방장 (시작 가능) | `START GAME` | 카운트다운을 건다 |
| 모두 (세는 중) | `3` `2` `1` | — |

방장 자신의 준비 상태는 시작 조건에서 보지 않는다. 시작을 누르는 사람이 자기 준비를
기다릴 일은 없다. **방장을 뺀 모두가 준비하면** 단추가 `START GAME` 이 된다.

눌렸다는 것은 **흐리기로** 말한다. 눌린 모습이 따로 그려진 그림이 있지만, 낱장마다
다듬긴 여백이 달라 같은 자리에 그려도 판이 한 번 튀었다 돌아온다.

## 3. 방 규칙과 기기 설정은 다른 것이다

설정 화면을 두 장으로 가른 기준이 이것이다. 사는 곳이 다르다.

| | 방 규칙 | 기기 설정 |
|---|---|---|
| 무엇 | 맵 크기 · 시드 · 아군 오사 · 본진 보호 · 동시 COM 수 | BGM · SFX 크기 |
| 누가 정하나 | 방장 | 각자 |
| 어디에 걸리나 | 그 방의 모두 | 그 기기만 |
| 언제 굳나 | 판을 열 때 (START) | 손을 떼는 즉시 |
| 어디에 남나 | 아무 데도. 방과 함께 사라진다 | `SharedPreferences` |

방 규칙은 `Messages.Start` 한 통에 실려 모두에게 간다. 로비에 있는 동안에도 `LOBBY`
패킷에 함께 실린다 — 방장이 고치는 즉시 내려가고, 규칙이 바뀌면 참가자 준비가
풀린다(무엇에 준비했는지 모르는 준비는 준비가 아니다). 맵은 seed 로만 보내므로
(→ [NETWORK.md](NETWORK.md) §2) 규칙이 한 사람이라도 다르면 **다른 맵이 만들어진다.**
그래서 참가자가 고른 값은 START 를 받는 순간 통째로 덮어써진다.

BGM · SFX 아이콘은 그 갈래의 음소거 단추다. 누르면 0 이 되고 다시 누르면 끄기 직전
크기로 돌아온다 — 슬라이더를 끝까지 끌었다 되돌리게 하지 않는다.

소리 크기는 반대다. 남의 귀까지 정해 줄 이유가 없어 네트워크에 싣지 않는다.
매니페스트가 정한 소리별 크기에 이 배율을 곱하므로, 총성과 폭발음의 상대적인
크기 관계는 그대로 두고 전체만 줄어든다.

### 본진 보호

한 발에 판이 끝나 버리면 마지막 순간에 손 쓸 도리가 없다. 켜 두면 본진이 첫
포탄을 한 번 막아 내고 (`TileMap.baseShielded`) 그 뒤에는 사라진다. 폭발도 마찬가지로
보호막을 먼저 먹는다.

보호막과 **내구도**는 다른 것이다. 내구도(`balance.json` 의 `rules.baseHits`)는 방
설정이 아니라 밸런스 값이고, 기기 여러 대로 시험하며 한 발 → 두 발 → **네 발**로
올려 왔다. 두 발은 COM 이 본진 앞에 서면 1초 남짓이라 달려갈 짬이 없었다. 보호막은
그 위에 한 발을 더 막으므로, 켜 두면 다섯 발까지 버틴다. 한 발이라도 맞은 본진은
손상된 그림(`base_damage_1`)으로 갈아 끼워 멀쩡하지 않다는 것을 보이게 한다.

### 동시 COM 수

총 COM 수와 다른 것이다. 총량은 플레이어당 20기(4인 80기)로 고정이고, 이 값은 **한
순간에 필드에 서 있을 수 있는 수**다. (계획서 §9, §44.2)

슬라이더의 맨 왼쪽 한 칸은 `AUTO` 다. 정하지 않으면 `balance.json` 의 인원별 값을
쓴다 — 2인 8 · 3인 10 · 4인 12. 손으로 정하면 8~12 안에서만 고를 수 있다. 계획서
§44.2 가 정한 폭이고, 더 줄이면 판이 늘어지고 더 늘리면 화면이 COM 으로 덮인다.

AUTO 를 눈금 하나로 둔 이유는, 손으로 한 번 정하고 나면 "인원에 맞춰 알아서" 로
되돌릴 길이 없어지기 때문이다.

### 아군 오사

끄면 같은 편 포탄이 서로를 지나간다 (`GameWorld.Config.friendlyFire`). 적에게는
그대로 들어간다.

## 4. 결과 화면

순위는 처치 수 → 남은 Life → 남은 HP 순으로 가른다. (계획서 §16.2)

**PLAY AGAIN 은 방장만 누른다.** 방을 다시 여는 일이라 각자 누르면 서로 다른 판이
열린다. 방장이라도 **다른 사람이 모두 결과 화면을 떠났으면 누를 수 없다.** 다시 열어야
최소 인원 두 명(§28)을 못 채우기 때문이다.

누가 남아 있는지는 참가자가 스스로 알린다.

```
Client -> Host   PRESENCE(true)    결과 화면에 들어왔다
Client -> Host   PRESENCE(false)   로비로 / 메뉴로 떠났다
```

방장 화면의 각 줄 오른쪽 등이 그 값이다. 잠긴 버튼만 두면 고장으로 읽히므로
버튼 아래에 왜 잠겼는지도 쓴다.

PLAY AGAIN 은 로비를 거치지 않는다. 결과 화면에 남아 있다는 것 자체가 "다시
하겠다"는 뜻이라 준비를 다시 받을 이유가 없다. 남지 않은 사람은 그 자리에서 빠진다.

혼자 하는 판(→ §1)에서는 같은 자리에 **RESTART** 라고 쓴다. 여기서 하는 일은 다음
판으로 넘어가는 것이 아니라 **같은 난이도를 새 맵으로 다시 여는 것**이다. 스테이지
번호와 인원을 그대로 두고 seed 만 새로 뽑는다. 밸런스를 보려고 여는 판이라 난이도가
같아야 견줄 수 있다. 로비 단추는 잠근다 — 돌아갈 방이 애초에 없다.

## 5. 카운트다운 소리

방장이 START 를 누르면 로비의 모두에게 세 번 울리고 마지막에 출발 신호가 난다.
남은 틱 수는 `LOBBY` 패킷에 실려 오므로 참가자도 같은 순간에 듣는다. 화면의 숫자만
두면 조이스틱에 손을 올려 둔 사람이 못 본다.

## 6. 네트워크 지연 표시

전투 중 HUD 구석에 이 기기의 왕복 시간이 ms 로 나간다.

```
Host <-> Client   PING(보낸 시각)
Host <-> Client   PONG(받은 시각 그대로)
```

두 기기의 시계를 맞출 필요가 없다. 값을 해석하는 쪽이 언제나 보낸 쪽이라, 돌아온
값을 제 시계에서 빼면 그것이 곧 왕복 시간이다.

- **평균이 아니라 내 기기의 값이다.** 화면이 튀는 것이 내 탓인지 남의 탓인지
  모르면 아무것도 할 수 없다. 방장은 가장 느린 상대를 따른다 — 한 사람만 늦어도
  그 사람의 화면이 늦기 때문이다.
- 참가자 쪽 값은 조금씩만 반영해 흔들림을 누른다. 숫자가 쉴 새 없이 바뀌면
  읽을 수가 없다.
- 색으로 한 번, 숫자로 한 번 말한다. 색만으로는 얼마나 나쁜지 모르고, 숫자만
  두면 좋은 값인지 나쁜 값인지 판단할 기준이 없다.

| 왕복 시간 | 표시 |
|---|---|
| ≤ 60ms | 초록 |
| ≤ 180ms | 주황 |
| 그 위 | 빨강 |
| 끊김 | `LOST` |

## 7. 화면비는 16:9 로 고정한다

```
 21:9 단말                       4:3 단말
┌──┬──────────────┬──┐          ┌────────────────┐
│  │              │  │          ├────────────────┤
│  │    16:9      │  │          │      16:9      │
│  │              │  │          ├────────────────┤
└──┴──────────────┴──┘          └────────────────┘
```

단말 화면비에 맞춰 늘리지 않는다. 늘리면 가로로 긴 기기에서 발사 단추가 엄지에서
멀어지고, 세로로 짧은 기기에서는 글자가 납작해진다. 한 비율로 고정하고 남는 곳은
검은 띠로 둔다. 그러면 어느 기기에서나 같은 화면이다.

`render/StageBox.kt` 가 그 조각을 계산한다. 게임 월드(`Viewport`), UI 화면
(`ScreenUi` · `LobbyScene`), 조작 UI(`TouchControls`)가 모두 같은 조각을 쓴다.
셋이 서로 다른 자리를 기준으로 놓이면 맵과 단추가 어긋난다.

화면을 그리는 코드는 조각 안쪽 좌표만 다룬다. 바깥 좌표로 옮기는 일은 두 군데에서만
한다 — 그릴 때 원점을 더하고, 손가락을 받을 때 원점을 뺀다.

HUD 는 그래서 맵 위에 겹친다. 예전에는 가로로 긴 기기에서 남는 띠를 HUD 자리로
썼는데, 그러면 기기마다 HUD 자리가 달라진다. 16:9 기기에는 애초에 그 띠가 없다.

## 8. 판 그림을 늘리는 법

메뉴 · 설정 · 결과의 판은 저마다 다른 비율로 그려져 있다. 아무 크기나 넣으면
걸쇠와 모서리가 뭉개져서, 같은 팩에서 온 그림인데 서로 다른 물건처럼 보인다.

- 네모난 것(배지 · 카드 · 아이콘)은 `ScreenUi.fitByWidth` / `fitByHeight` 로 비율을
  지킨다.
- 띠 모양(제목판 · 버튼 · 순위 줄)은 `ScreenUi.bar` 로 **세 조각으로 나눠 가운데만**
  늘린다. 어떤 너비에서도 끝 모양이 그대로 남는다.
- 글자와 조작기는 판 안쪽의 **안전한 자리**에만 놓는다. 네 귀퉁이의 걸쇠 장식은
  판을 아무리 넓게 늘려도 크기가 그대로라(끝 조각은 원래 비율로 그린다), 여백을
  판 너비의 비율로 잡으면 넓은 화면에서 걸쇠 위로 글자가 올라간다. 끝 조각의
  크기를 기준으로 잡아야 어느 화면에서나 비껴간다.
- 글자는 판 한가운데가 아니라 **속판** 한가운데에 놓는다. 판 그림에는 위아래
  테두리 두께가 서로 달라서, 글자 자리는 사각형 한가운데와 다르다.
  (→ [ASSET_SELECTION.md](ASSET_SELECTION.md))
